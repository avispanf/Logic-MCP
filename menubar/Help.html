Logic MCP

One shared backend for Logic Pro, with a manual-work switch. Start with a copy of a project.

First installation

  1. Open Logic MCP.app and click Install & connect. On a fresh install it copies itself to your Applications folder, installs the shared service and configures Codex and Claude Desktop with backups. Existing apps are not overwritten.
  2. If macOS blocks this unsigned developer preview, follow Apple's Open Anyway instructions only if you trust the download. Never disable Gatekeeper globally. Right-click the top button → Install & connect Codex + Claude to retry setup.
  3. Choose Reveal permission helper. Finder selects the exact installed logic-mcp executable. Choose Accessibility settings and use + to add that executable. Only you can approve Touch ID or your Mac password.
  4. Choose Enable NEW automation. Open Logic and approve Automation access to Logic Pro and System Events when macOS requests it.
  5. In Logic → Control Surfaces → Setup, use one Logic Control / MCU-compatible surface and assign both input and output to LogicProMCP-MCU-Internal [bridge]. Keep unrelated hardware controllers unchanged.
  6. Open Diagnostics, then restart Codex/Claude Desktop when convenient. Their configuration is already installed. The first backend connection populates the tool cache, so enable once before reloading clients. Diagnostics can copy detailed status for troubleshooting.

For the shared service, Accessibility belongs to Logic MCP.app/Contents/Resources/runtime/logic-mcp. Granting only the menu app or bin/LogicProMCP is not sufficient. The mode button itself needs no Accessibility permission.

Connect your MCP client

The installer configures both Codex and Claude Desktop. Only the three Logic MCP entries are updated; unrelated settings and tool restrictions are preserved. Claude's STDIO relay connects to the same shared backend instead of creating new MIDI ports. For other clients, Copy MCP client configuration copies a TOML example using the actual installed path.

Example for an app installed in the system Applications folder:

[mcp_servers.logic-pro]
url = "http://127.0.0.1:8765/mcp"
tool_timeout_sec = 180

[mcp_servers.logic-plugins]
command = "/Applications/Logic MCP.app/Contents/Resources/runtime/logic-mcp"
args = ["--plugins"]

[mcp_servers.logic-audio]
command = "/Applications/Logic MCP.app/Contents/Resources/runtime/logic-mcp"
args = ["--audio"]

Reload your client after changing its configuration. End users do not need Python, a compiler, a source checkout or Homebrew for the mode switch and plugin control. Audio-file loudness analysis additionally requires ffmpeg/ffprobe.

Everyday use

Left-click the top button to switch modes; right-click for explicit Manual mode — MCP OFF and Enable NEW automation actions. The floating button is optional. Turning off the floating button does not disable the service.

MANUAL · MCP OFF
Manual mode is verified. New automation requests are rejected. Re-enabling cancels old paused jobs; start a new request.
MCP ON
The latest readiness check passed. Individual edits still require independent readback.
MCP · MCU check
MCU feedback is old. This can happen while stopped and does not by itself mean ports disappeared. Readiness remains unverified. Check the assignments and Logic's Bypass All Control Surfaces setting if commands do not work.
MCP · access / setup MCU / offline
Follow the tooltip and Diagnostics for the missing permission, port assignment or service.
MCP CHECK
The mode could not be verified. A left-click requests manual mode; it does not silently enable automation.

The MCU ports disappear in manual mode and return after enabling, keeping stable identities. A change once per mode transition is expected; repeated changes while the mode stays unchanged are not.

Pausing an audit may interrupt its restoration steps. Inspect solo, mute, transport and plugin settings before starting another task. The button does not change project settings or repair an interrupted mix automatically.

Updates, recovery and removal

Ad hoc development updates can invalidate an Accessibility grant while its switch still looks enabled. Remove only the old logic-mcp entry, reveal the current helper, add it again, then verify Diagnostics. Do not reset other applications' permissions. A missing bundled runtime requires reinstalling the complete app.

Repair manual state backs up damaged state and keeps automation blocked. Remove service cancels old workers and removes the login service; the manual barrier is deliberately retained. Remove MCP client entries, quit the app and move it to the Trash. Keep audit journals for manual recovery.

Scope of the beta

Tested on Apple Silicon with macOS 26.6 and Logic Pro 13.0; earlier work used Logic 12.3. The build targets macOS 14+, but runtime validation on that minimum OS is outstanding. No guarantee covers every plugin parameter, instrument, group or analyzer meter. Unreadable states are not guessed.

GitHub developer previews are ad hoc signed and not notarized; an Apple developer account is not required to share them. Developer ID signing/notarization can be added later for smoother startup. Clean-Mac and minimum-OS runtime tests remain separate from packaging checks.
